# kolpick 设计和已定的事

kolpick 的产品依据：要做成什么样、各块怎么工作、已经定了什么。别的文档和它冲突时以这里为准；要改方向，先改这里。2026-10-27 和用户逐条重新定过，取代之前的所有设计文档（旧版在 git 历史里，不再作为依据）。

## 一、原则

1. **大脑是通用 agent。** 找什么人、怎么筛、给谁发、信怎么写、怎么跟进，由运营电脑上的 agent 决定和做。不绑定某一家：第一版接 Claude（Claude Code）和 Codex；Grok 以后再接。
2. **工具是手脚，agent 和人都能用。** 找人（Apify）、查邮箱、收信、发信、建码、同步数据、读写数据，做成可靠的工具。agent 能调用，运营也能在决策台直接点。
3. **日常的事 agent 提、人审、过了就做。** 回信、催信、发码、各种草稿，agent 提出来，运营在决策台审核；审核通过就去做，工具直接做或 agent 再调工具做都可以。发出去的必须是运营在决策台同意的那一版。
4. **决策台点了，要 agent 接着做的，自动做完。** 「让它改」、来信起草、码过期写信、邀约批次发出、结果不明和退信的处理，都是点了就由决策台在后台叫本机 agent 做完，运营不用再去 agent 里说一句。
5. **全装在运营的电脑上。** 谁都可以装；同一时间只有一个人发起任务。不登录、不分账号、不认领执行电脑，近期不上服务器。云上只放数据库。

## 二、怎么接 agent

- **手脚和规则做成一个本机 MCP 服务**（Streamable HTTP），也能当命令行用。规则写成一份由 MCP 提供的说明。Claude、Codex 等能接 MCP 的 agent 都用同一套。
- **运营在 agent 里直接用**：在本机 Claude 或 Codex 里问「今天运营做了哪些」、叫它找人、起草，都通过 MCP 读写数据库。
- **决策台在后台叫 agent**：调用本机的命令行 agent，用运营已付费的订阅（默认 `claude -p`，设置里可换 `codex exec`）。设置里填的是命令，以后加别的 agent 只加配置。后台每次干活都是一个留在本机的会话，之后能打开接着聊（会话编号显示在决策台）。后台同时最多做 3 件（设置里可改），同一位 KOL 的事一件做完再做下一件。调 agent 时去掉从别处带进来的 API 密钥类环境变量，`claude` 还不读运营个人的 `~/.claude/settings.json`（那里可能配了中转地址和密钥），确保用的是运营自己的订阅登录；Codex 要设成 kolpick 的工具自动放行。
- **一个本机进程**：决策台页面、MCP 服务、收信监听、定时任务在同一个本机服务里（只听 127.0.0.1）。安装时设成开机自启（macOS LaunchAgent），所以 agent 随时能用 MCP；决策台就是浏览器里打开的这个页面。
- **Grok**：xAI 的 Grok 应用只接公网上的 MCP（拒绝本机和内网地址），要接得加隧道和密钥；也还没有能在命令行自己跑完任务的 Grok。以后再接，手脚和规则不用改。

## 三、各块怎么做

**找人**：两种都要。
- 跟 agent 说（如「找 30 个做日本旅行的 YouTube 博主」），agent 调 Apify 找、查邮箱、筛，给决策台一张「这批要不要入库」。
- 运营在决策台自己填条件找，找到的直接入库。

**邀约**：不让 agent 挑人，有邮箱的都邀约，越多越好。每批出一张卡片，运营点一下就发。限制：每日额度、退信率暂停、永不联系、跨项目冷却（同一邮箱在别的项目冷却期内联系过不邀约）。

**收信和回信**：
- 用 `lark-cli mail +watch` 实时监听每个发信邮箱（飞书长连接，不需要公网地址）。来一封人类来信，agent 马上起草回复（要发码的带上参数），进决策台；运营同意就发，不满意点「让它改」，自动重写后回到队列。
- 电脑关着时的信不会补推：每次打开先按时间补收一遍，再开始监听。来信按邮件编号去重，多读不重复处理。
- 对不上人的来信、退信，agent 先判断是谁、怎么处理，运营点确认。
- 2026-10-27 已试通：应用开了 `mail:event`、`mail:user_mailbox.event.mail_address:read`，订阅了 `mail.user_mailbox.event.message_received_v1`（长连接），运营授权后几秒内收到事件。监听断了每 2 分钟补收一次，平时每 15 分钟补收一次兜底。飞书邮箱里手动发给 KOL 的信也补记进来往。

**跟进和催信**：催信和无回应结案都要审核。工具按设置的天数找出该催、该结案的，用在用的「催信 1」「催信 2」模板起草（接在原来的邮件串里），排成一组；运营可以整组同意，也可以剔掉几个，对单封不满意就在卡片上改。

**建码**（体验码、延期、开活动码）：agent 在回信里提出发码，同意后先建码再发信。码过期时 agent 判断延期、换码还是收尾，起草好信给运营。

**发布**：自动找帖子，显示谁发了视频、链接、发布后第 1、3、7、30 天的播放和互动。约好没发的，agent 起草问询信。

**效果分析**：先不做面板。数据都在库里，要看时让 agent 读数据分析。

**设置**：
- 规则（额度、催信和结案天数、冷却、码的默认值等）和发信邮箱，在决策台直接改。
- 模板两种改法都要：决策台里自己编辑；或说怎么改，agent 起草新版，决策台对比新旧后批准。改在用的模板只存成草稿，在用版本照常发，新版批准后才换。
- 接口密钥、数据库连接串只存在本机，不进页面。

**决策台**：运营集中做决定的地方。页面样子和每个按钮的交互以 UI/UX 设计稿为准（claude.ai 上的「kolpick 决策台设计」画布，9 页，每页下面有交互说明）；这里只记定下的规则。四个页面：待你决定、KOL、记录、设置。
- **待你决定**：左边队列，右边卡片详情。按「要你做什么」分五组：出问题了（退信、对不上人的来信、结果不明、失败，固定排最上面）、回一封信（回信、主动写信、码到期、问发布、单封催信）、发一批（邀约批、催信和结案批）、要你拍板（不用回、建议结案、超出规则要你定的事、agent 找到的人、模板新版）、已处理。卡上的小标签写来源。分组由卡片的类型和状态算出来，不单独存。每张发信的卡写明「同意后会依次做」的步骤；草稿可以直接改，改过的按改过的发。同意或不做之后 5 秒内可以撤销，处理完自动跳到下一张。「让它改」写意见交给 agent，改好的卡回到队列最上面。结果不明的事在页面顶部用红条请运营确认。暂停所有发送时照样能同意，卡片排队，恢复后按同意顺序发。
- **KOL**：KOL 页是核心。列表按阶段和「要注意的」（轮到我们、码快到期、过了约定日、退信未处理、发了帖子）筛，能搜、能排序。每行直接显示阶段和轮到谁、最近来往、下一步、码的用量、发布（几条、最新一条的播放）；点开一行就在列表里展开最近来往、码和成交、每条帖子第 1/3/7/30 天的数据，不用跳页。勾选后可批量让 agent 起草、改阶段、暂缓；勾的全是未联系时可放进一批邀约。列表页不直接发信。详情页有全部来往、卡片历史、资料、记录，能写信（点发出就算同意，同样 5 秒可撤销）、改状态、结案（选原因）、永不联系（说明影响、确认后才生效）。「找新的人」从 KOL 页进。
- **记录**：发生过的每件事一条一条按时间排，不区分是谁做的：运营在决策台点的、在 Claude / Codex 桌面版里叫 agent 改的、后台自动做的，只要改了数据或对外做了事都记一条，写清做了什么、对谁、结果，能点到 KOL 和卡片；出错的标红。只查不改的不记。顶部显示今天的数字和 agent 正在起草的事。
- **和 agent 来回商量的事在 Claude / Codex 桌面版里说**，决策台不做聊天。后台 agent 卡住时，决策台只给「看原信」「原样再试」和接着聊的命令。
- **设置**：发信和额度（含发信邮箱、预热）、催信和结案、体验码和活动码、模板、找人和找帖子、自动运行、这台电脑。改了出现保存条；切换数据库要二次确认；顶部标签显示当前是正式库（红）还是测试库（灰）。
- 运营自己动手的功能都保留：找人、写信、改资料、改阶段和日期、结案、永不联系、暂停所有发送。
- 定时的事（催信扫描、同步码用量、码到期和约好没发、找帖子、抓数据）由本机服务每天跑一次，错过的下次启动先补跑；不再用 Claude 的定时任务。
- 收信监听、定时任务、后台 agent 各有一个开关，在设置页「自动运行」；新装和切换时默认关着收信和定时，运营点头后再开（上线步骤的停三）。
- 出问题时的样子：本地服务连不上时整页提示并自动重连；某个邮箱实时收信断了时顶部橙条，降级为定时补收；后台任务出错时红条写明哪一步、什么原因。

## 四、必须守住的规则

- 一位 KOL 在一个项目里同时最多一封待发的信。
- 同一封来信只记一次，重复读到不改任何状态。
- 批准的是卡片上那一版内容；批准后内容变了或对方又来信，批准作废。
- 结果不明的外部动作（超时、断线）不自动重做，等运营确认；已经成功的不做第二次（码建了不再建，信发了不再发，延期做过不再延）。
- 永不联系只算当前项目；永不联系的不发任何信，同一邮箱属于永不联系的 KOL 时，用这个邮箱的其他 KOL 在本项目也不发。
- 「暂停所有发送」开着时不开始任何外发和建码，收信照常。
- 每日额度：项目每天联系的人数、每个邮箱每天的人数（含预热）。
- 退信：邮箱最近 14 天退信率达到 6%（至少发过 20 封）暂停这个邮箱；有未处理的退信时挡住发往该地址的信，处理后解除。
- 外部动作一件一件做。

## 五、数据

- **放在哪**：Zeabur 项目 `untitled` 里的 Postgres 服务 `kol-find`（新加坡），只给 kolpick 用，不进 TAFU 正式业务库。建两个库：`kolpick_prod`（正式）和 `kolpick_test`（测试）。一个库里可以放多个业务项目，用项目区分。
- **表结构**：按本文件重新设计（之前的 22 张表设计作废），写在代码的迁移里（`src/kolpick/db/migrations.ts`），不另写文档：项目和规则、发信邮箱、模板、KOL（档案和跟进合成一张）、来往、码、帖子、卡片、外部动作、后台任务、日志、少量状态。一位 KOL 一封待发、同一封信只记一次、同一张卡片的外部动作只做一次，由数据库的唯一约束挡住。
- **旧数据**：上线时从最新的飞书多维表格全部导入：KOL、跟进、来往邮件、模板、设置、旧审核单、运行记录、操作日志、发布数据。不做核对报告，数条数、抽看几位 KOL。
- **切换后删掉**：读写飞书多维表格的代码、Postgres 里 `kol.*` 原样搬库和本机副本。飞书表留作只读存档。飞书只剩邮箱收发、通讯录、群通知。
- **现行旧版**：切换前，正式 tafu 仍由旧版插件跑在飞书表上，`plugins/kol-ops/README.md`、`reference/`、`skills/` 描述的是旧版，切换时随新代码一起重写，之前不动。

## 六、上线步骤

1. 在 `kolpick_test` 建表，导入最新飞书数据，做完全部功能。测试库的发信邮箱一律停用。跑自动测试，再用本机 Codex 做浏览器测试和代码审核。
2. **停下，等运营在测试库上用一遍点头。**
3. 正式切换：暂停所有发送，用旧版最后收一次信；飞书表设为只读；导入 `kolpick_prod`，数各类条数。
4. **停下，等运营抽看几位 KOL 点头。** 这之前都能退回旧版（飞书表恢复可写）。
5. 换成新版，补收一次信。
6. **停下，等运营看过补收的来信和决策台点头**，再开收信监听、定时任务和发送。从这里起只往前修，不回退。

## 七、和 TAFU 运营后台的分工

**跟人打交道的在 kolpick，跟钱有关的在 TAFU 后台**（tafu-nodejs 的 `/admin`），两边只通过 `kol-data` 接口打交道（约定见 [data-api.md](data-api.md)）。

| 环节 | 归谁 |
| --- | --- |
| 找人、邀约、来信、审核、跟进阶段、找帖子和抓数据 | kolpick |
| 发体验码、延期、开活动码 | kolpick 发起并批准，TAFU 执行；码和活动存在 TAFU |
| 码的用量、活动访客、付款订单、退款订单 | 以 TAFU 为准，kolpick 每天同步数字，不同步金额；同步失败保留上次的值，不当成零 |
| 分润规则、账本、结算、付款、退款；改活动规则、停用、重置账本 | 只在 TAFU 后台 |

- 开活动码时存下 TAFU 返回的合作方编号，KOL 页面放「在 TAFU 后台查看」。
- 不传 KOL 联系方式给 TAFU，唯一例外：经批准开活动码时，只传这位 KOL 的联系邮箱。月度结算不迁移，以 TAFU 后台为准。

## 八、找人和查邮箱

2026-10-20 调研、用 150 个历史 KOL 实测后定下的做法。代码在 `src/discovery/`，actor 和单价以 [apify.ts](../src/discovery/apify.ts) 为准。

- 找人和查邮箱都用 Apify 商店里现成的 actor，不自己维护爬虫，也不用 CreatorDB 等达人数据库（只在需要互动率、粉丝画像或某品类扩不出人时做备选）。
- 「分层瀑布」查邮箱：先用最便宜的方式，查到就停，贵的只用在前面都没找到的人身上。
- 命中率靠找人阶段挑对人（商业号、简介有外链），不靠换查邮箱的工具。
- 所有平台最后按粉丝数、账号类型筛一遍，再去重。

| 平台 | 找人 | 查邮箱 | 实测 |
| --- | --- | --- | --- |
| Instagram | 相似账号扩量（thenetaji/instagram-related-user-scraper）+ 短关键词搜（apify/instagram-search-scraper） | 读商业号公开邮箱字段（devil_port369-owner/instagram-email-phone-scraper-pay-per-result），读不到再跟外链（vdrmota/contact-info-scraper） | 旧名单 58/60 复现；新扩的人 42%–53% 有邮箱，每个邮箱 1.5–2 美分 |
| YouTube | 关键词搜频道 | 先读简介，读不到再查隐藏商务邮箱（dataovercoffee/Youtube-Channel-Business-Email-Scraper，找到一个 12 美分） | 简介 27/30，隐藏邮箱 29/30 |
| TikTok | 关键词搜用户 | 读简介 | 10/10；按关键词找人效果差，主要适合查已知账号 |

- **成本**：每 1000 个 KOL 约 8–15 美元（2026-10），YouTube 隐藏邮箱另算。外链找邮箱的 actor 批量跑时付费档更划算。
- **小红书**：还没做；博主很少公开邮箱，等三个海外平台跑顺了再抽样看。
- **风险**：actor 随时可能改价、失效或下架，每一步都要能换工具；YouTube 隐藏邮箱 actor 靠登录加验证码，可能哪天就停。给台湾、欧美 KOL 发商业邮件涉及個資法、GDPR、CAN-SPAM：写清发件人、不买别人整理的邮箱列表；合规边界没有正式核实过。

## 九、其他已定的事

- 新邀约都走飞书邮箱 hello@tafu.me、mei@tafu.me。tafuofficial 的 Gmail 不接，老邮件串手动收尾。
- 运营只有一位；运营批准模板；不做新旧模板 A/B 测试。
- 帖子数据用抓取工具定时抓。
- 插件和 TAFU 解耦，以后能给别的项目用，但现在只在代码里留扩展点（项目专属的体验码、活动码等收进项目模块），不做可配置的东西。
- 仓库公开（历史扫过，没有密钥）。`main` 上开发，同事从 `stable` 分支安装（发布流程见根目录 README）。
- 一种作用的文档只留一份。
