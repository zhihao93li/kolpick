# 决策台、飞书表、Claude 插件：分工和规则

2026-10-26 定。做本地决策台（插件里的 `kol console`）时按这里写代码和插件说明。

已实现（kol-ops 0.14.0，分支 console-readonly）：执行器锁和执行电脑（`kol executor`）、每封信前查暂停、执行前认领、同意来源和内容指纹、「只认决策台的同意」开关、决策台的全部按钮、一位 KOL 只留一封待发的信、陌生来信记录和关联、「你不在时发生的」。执行器的记账没有用 SQLite：状态以飞书为准，本机只有一个锁文件。

## 三条规则

1. **日常数据只在决策台改，规则和模板在飞书改。**
   - 只在决策台改（飞书里只看）：KOL 档案、KOL 跟进、审核队列、接触记录、发布内容。
   - 继续在飞书里改：设置、发信邮箱、模板（正文）、各种选项。这些改得少，基本只有管理员改。
   - 决策台里保留「暂停所有发送」和「批准模板」（一种待决定的卡片）。
2. **只有一个执行器，所有动作排队，一件一件做。** 执行器在运营那台电脑上，别的电脑上的插件一律不执行。
3. **Claude 只做准备。** 分类、写草稿、按意见重写、补全资料、整理找人的结果、回答问题。它产出的东西都进「待你决定」，不直接执行。

从决策台上线那天起，在飞书里点「发／同意」不再算数，不设过渡期。

## 执行队列

### 什么会进队列

所有会改动外部的动作：发信（回信、邀约、催信）、建体验码、延期、开活动码、收信、找人（花 Apify 的钱）、找帖子和抓数据、同步体验码用量。

来源有三个，都只是往队列里放：

| 来源 | 放进去的 |
| --- | --- |
| 决策台 | 你点「同意」的事、「找新人」、「记下这条发布」、改字段 |
| 每日例行（Claude 定时任务） | 收信、催信和结案、找帖子、抓数据、同步体验码 |
| 在 Claude 里手动说 | 比如"把这封发出去"、"再找一批人" |

### 执行器怎么跑

- 一台电脑上只有一个执行器在跑，用本机的锁文件保证。`kol console` 启动时带起执行器；早上的例行任务运行时，如果执行器没在跑，就自己当一次执行器，用的是同一把锁。
- 「设置」里记一项「执行电脑」（插件生成的电脑编号）。别的电脑上的插件发现自己不是这台，就拒绝放会执行的东西，只能看、写草稿、提交待决定。
- 决策台开着时，执行器每 10 分钟收一次信；电脑关着时就不收，第二天早上的例行会把收信排进来。

### 每件事执行前后

1. 看「暂停所有发送」，开着就停在这里，不往下做。
2. 重新读「设置」「发信邮箱」「模板」（每批读一次），额度、预热、模板状态都以最新的为准。
3. 从飞书重新读这一条，核对：还在等执行；内容指纹和同意时的一样（见下）。对不上就不做，退回「待你决定」并说明原因。
4. 先在飞书里把这一条标成「执行中」，再去做（建码 → 发信）。
5. 做完写回结果：接触记录、跟进状态、执行记录；建码、开活动码、延期的结果也写进这一条，重试时先看这里，不会做两次。
6. 结果不明（比如发了没收到回执）的，不自动重做，进顶栏和执行记录等人确认。

### 放进队列时就要挡住的

- 同一个人同一时间最多一件要发信的事。她又来了新信，旧草稿作废，交给 Claude 合并重写成一封。
- 同一封来信（Message ID）只收一次。

## 同意

- 只认决策台上点的同意。同意时写进审核队列：同意来源（决策台）、同意人、同意时间、**内容指纹**（主旨、正文、收件人、发信邮箱、附带动作的参数）。
- 执行前再算一次指纹，对不上就退回重看。Claude 按意见重写后，原来的同意自动作废（现有 `revise --apply` 已经这样做）。
- 审核队列的「处理」一列加说明：请在决策台里同意，这里改了不会执行。

## 先不做的

- 技术上禁止人改飞书（让插件改用飞书应用身份写入，再把日常表格设成"人只能看"）。先靠约定，真出了问题再加。
- 决策台里的设置页。

## 待定

- **执行器的记账用不用本机 SQLite**（2026-10-26 提出，做执行器时再定）。要记的是队列、每件事的执行状态、建码和发信的结果、锁。现在的本机发送日志是一个追加写的 `~/.kol-ops/sends.jsonl`。

## 附录：排查过的冲突和去向

对照 kol-ops 0.12.x 代码查过的 12 处，现在都由上面的规则或队列解决：

| 冲突 | 现在的代码 | 怎么解决 |
| --- | --- | --- |
| 同一封信发两次 | 发信锁只在开始时查，30 分钟自动放行；发送日志只在本机 | 只有一个执行器，一次一件 |
| 同意后内容被改，发出去的不是你看过的 | 飞书里手改发现不了 | 人不改日常表 + 指纹核对 |
| 在飞书里点同意 | 会执行 | 只认决策台的同意 |
| 决策台数据过期 | 无 | 执行前重读这一条；页面定时只读改过的行 |
| 同一个人两封待发的信 | 来信处理不查已有待审核 | 放进队列时挡住，合并重写 |
| 收信同步同时跑两次，来信记两遍 | 收信不在锁里 | 收信也由唯一的执行器做 |
| 按了暂停，正在发的一批没停 | 只在一批开始时查 | 每件事前都查 |
| 体验码延期执行两次 | 只靠本机日志 | 结果写进飞书 + 只有一个执行器 |
| 已结案的人又来信 | 阶段还停在结案 | 卡片写明"之前已结案"，给"重新跟进"的选项 |
| 刚回信的人被催一次 | 只在收信和发催信之间的几分钟里会漏 | 发催信前查这一位有没有新来信 |
| 两边同时改同一个字段 | 只写改了的字段，不整行覆盖 | 人不改日常表；决策台也只写改了的字段 |
| 飞书里改了规则，决策台不知道 | 命令开始时读一次 | 执行器每批重读 |
