# kolpick 决策台界面说明

这份文档写决策台**长什么样、怎么操作**：每个页面放什么、每种卡片和表单的控件、各种状态怎么显示。规则（什么时候出卡片、按了会发生什么）只写在 [产品行为规格](behavior.md)，这里用它的编号引用（C-xx 卡片、E-xx 事件、G-xx 闸门）。为什么这样定看 [design.md](design.md)。

界面元素也编号：页面 U-x，表单和对话框 F-xx。改页面代码时按编号对照；设计稿在「KOL 决策台设计稿」画布（https://claude.ai/artifact/1tUT5MD8obQ9GmvQwkUSE8）里，每张画板标了对应编号。

## 1. 设计原则

1. **一位运营、一台电脑、每天几十件决定。** 打开就是今天要做的事，一件一件处理，不用找。
2. **一屏做完一件事。** 处理一张卡片需要的信息（她说了什么、我们发过什么、码的情况）和要做的操作都在同一屏，不跳页。
3. **按钮说后果。** 按钮文字是动作本身（「同意并发出」「结案」），旁边一句话写按了会怎样（「5 秒后发给 deer@example.com」）。
4. **能撤销的就不确认，不能撤销的才确认。** 普通操作点了就做，5 秒内可撤销；不可逆的（永不联系、结案、确认已发出）在按钮所在位置就地展开确认条，不用浏览器弹窗。
5. **不用浏览器自带弹窗。** 所有输入都在卡片里的表单或右侧滑出的面板里，用日期选择器、下拉框，当场校验格式。
6. **状态一直看得见。** 暂停发送、不是执行电脑、数据是多久前读的、正在执行什么，都在顶栏或横幅上，不藏在菜单里。
7. **数字带来源和时间。** 用量、粉丝数、退信率都写清楚是哪天、从哪里来的；不知道就写「不知道」，不写 0。
8. **键盘能做完。** 待你决定页的常用操作都有单键快捷键。

## 2. 全局框架

### 2.1 顶栏（所有页面）

从左到右：

| 元素 | 内容 | 交互 |
| --- | --- | --- |
| 品牌和项目 | 「KOL 决策台」＋当前项目名 | 有多个项目时，项目名是下拉，切换后整页重读 |
| 页签 | 待你决定（带待办数）、KOL、执行记录、设置 | 当前页高亮；待办数为 0 时不显示数字 |
| 状态胶囊 | 一个圆点＋一句话：「空闲」「执行中 2」「暂停中 · 3 件排着」「有 1 件没做成」 | 点开下拉面板，列出正在执行和没做成的事，每条可跳到对应卡片 |
| 数据时间 | 「12:22 已同步」 | 超过 30 分钟变橙色 |
| 刷新 | 重读数据 | 读取中按钮显示转圈，不可重复点 |
| 暂停所有发送 | 红色描边按钮；暂停时变成实心「恢复发送」 | 暂停立即生效（E-50）；恢复时就地确认「恢复后会发出排着的 N 件，确定？」 |

### 2.2 横幅（顶栏下方，按优先级只显示最重要的两条）

| 情况 | 横幅文字 | 颜色 |
| --- | --- | --- |
| 暂停所有发送 | 已暂停所有发送：你同意的事会先排着，点「恢复发送」后才执行。 | 红 |
| 不是执行电脑（G-10） | 这台电脑不是执行电脑，只能看和提交决定，执行要在「某某的电脑」上做。 | 橙 |
| 有邮箱没收全（G-3） | hello@tafu.me 这次没把信收全，今天先不催信、不结案。去「执行记录」看详情。 | 橙 |
| 有来信对不上人（G-2） | 有 2 封来信还对不上 KOL，今天先不自动催信和结案。[去处理] | 橙 |
| 表缺字段、还没设置好 | 现在的说明＋「去设置」链接 | 橙 |

### 2.3 提示条和撤销

- 底部居中，一次一条：「已同意：5 秒后发给小鹿 [撤销 Z]」。5 秒倒计时条走完才真正提交（E-22）。
- 撤销后卡片回到原位，提示「已撤销」。
- 出错时提示条变红，写原因和下一步（「没发出：她今天已经收过信，明天再发」），停留到点掉为止。

### 2.4 侧滑面板和对话框

- **侧滑面板**（从右侧滑出，宽 480px）：写信、找新人、改跟进、加邮箱这类要填几项的表单。底部固定「取消」「主按钮」。按 Esc 关闭；填了内容再关闭时先问「放弃这封信？」。
- **就地确认条**：不可逆的操作，点按钮后在按钮下方展开一行「确定结案？原因：没回应 [确定] [取消]」，不另开窗口。
- **对话框**只用于选择列表（关联来信时选 KOL），居中、可搜索。

### 2.5 加载、空、出错

| 状态 | 显示 |
| --- | --- |
| 第一次读数据 | 页面中间：「正在读数据…第一次打开要一两分钟」，下面一条进度骨架 |
| 待你决定为空 | 「今天的事都处理完了」＋「你不在时发生的」摘要＋去 KOL 列表的链接 |
| 列表为空 | 说明这个视图放什么，例如「还没有约好要发布的人」 |
| 读不到数据 | 红色卡片：哪里读不到、原因、「重试」按钮 |

### 2.6 快捷键（待你决定页）

| 键 | 作用 |
| --- | --- |
| J / K | 下一件 / 上一件 |
| A | 主按钮（同意并发出、记下发布等） |
| R | 让 Claude 改 |
| D | 不做了 / 不用回 |
| S | 跳过（先看下一件） |
| Z | 撤销刚才的操作（5 秒内） |
| 1 / 2 | 卡片里的二选一（还没发 / 已经发了） |

输入框里打字时快捷键不生效。

### 2.7 颜色和组件

- 颜色沿用现在的变量：主色蓝（主按钮、选中），红（出错、退信、永不联系、危险操作），橙（等待太久、提醒），紫（来信），绿（完成）。
- 按钮三级：主按钮（实心蓝，每张卡片只有一个）、次按钮（白底描边）、文字按钮（危险操作用红字，不加框）。
- 徽章：卡片类型标签用彩色底徽章，见 4.1.3。
- 日期一律用日期选择器，显示「10 月 27 日（周二）」；跟今天比较的写相对时间「3 天后」。
- 邮箱输入框当场校验格式，失败时框下红字。

## 4. 页面

### 4.1 U-1 待你决定

#### 4.1.1 布局（三栏，宽屏 ≥1280px）

| 栏 | 宽 | 内容 |
| --- | --- | --- |
| 左：队列 | 320px | 按组排列的卡片列表；组顺序：出了问题、发布、回信、来信、跟进、邀约和决定、模板、其他。每组标题带数量，可折叠。每行：类型徽章、标题一行、副行（阶段 · 平台 · 粉丝）。当前卡片高亮，处理过的灰掉、可撤销期间显示「5 秒后执行」 |
| 中：内容 | 自适应 | 卡片标题、谁（链接到 U-3）、阶段条、系统建议、她的来信全文、最近来往（对话气泡，她在左、我们在右）、码的情况 |
| 右：操作 | 380px，吸顶 | 要我决定什么、草稿编辑区、参数、按钮、按了会怎样 |

窄屏（<1280px）时左栏收成顶部的「第 3 / 90 件」下拉，中右两栏上下排列。

顶部一行：「有 90 件要你决定」＋「你不在时发生的（折叠）」＋快捷键提示。另有一行灰字「另有 2 件在等 Claude 按你的意见重写」。

#### 4.1.2 卡片通用结构

中栏从上到下：

1. **标题行**：类型徽章＋一句话标题（「小鹿 来信，已经 3 天没人回了」）＋右侧「去她的页面」。
2. **身份行**：阶段 · 平台 · 粉丝数 · 收件邮箱。
3. **建议框**（浅蓝底）：系统或 Claude 的判断，一两句。
4. **她说的话**：最新来信全文，长的折叠，「展开」看全部；读不到正文时写「正文没读到，去邮箱里看」。
5. **最近来往**：最近 6 条对话气泡，「看全部」展开。
6. **码的情况**（有码时）：体验码 deer · 已用 1/3 · 11 月 5 日到期 · 用量 10 月 27 日同步。

右栏从上到下：

1. **要你定什么**：一句问题。
2. **按了会怎样**：编号步骤，例如「① 建体验码 deer（3 次，14 天）② 回信给 deer@example.com（从 hello@tafu.me）③ 她的阶段改成体验中」。
3. **草稿和参数**（见各卡片）。
4. **按钮组**：主按钮一个，次按钮若干，危险操作文字按钮放最后。下面一行小字快捷键提示。

### 4.2 U-2 KOL 列表

- **页头**：「KOL」＋「正在跟进 953 位 · 还没联系 629 位」＋右侧主按钮「找新人」（打开 F-02）。
- **视图页签**：等我们回、邀约没回、在试用、合作中、约好要发布、已发布、暂缓、跨项目联系过、全部在跟进的、还没联系（候选）。每个带人数。
- **一句问题**：每个视图上方一行灰字说这个视图回答什么（「先回谁？等得最久的在最上面」）。
- **搜索框**：搜名字、账号、邮箱，输入后 300ms 自动搜。
- **表格列**（全部在跟进的）：KOL（名字、账号、平台、粉丝）、现在的情况、等了、待你决定（有就显示徽章）、下次跟进。每个视图按自己的排序。点一行进 U-3。
- **还没联系（候选）**：列为 KOL、平台、粉丝、邮箱、入库批次、内容类型；可多选，顶部出现「交给 Claude 发邀约」提示（批量邀约仍在 Claude 里发起，E-03）。

### 4.3 U-3 KOL 详情

两栏：左宽右窄。

**左栏**

1. 返回链接、名字（大）、称呼、平台 · 粉丝。
2. **现在的情况卡**：一句状态（「约好 12 月 1 日发布」）、最后联系几天前；阶段条（已邀约 → 已回复 → 试用 → 合作 → 约好发布 → 已发布，当前高亮，暂缓/结案时阶段条变灰并加标签）。
3. **下一步**：文字＋下次跟进日期，旁边「改」打开 F-05。
4. **操作行**：写信给她（主，F-01）、暂缓 / 恢复跟进、不再跟进（F-06）、永不联系（F-07，红字）。暂缓时阶段条保持原阶段并加「暂缓」标签；现行飞书表的阶段会被改成暂缓，所以暂缓时在下一步末尾记下「（暂缓前：某阶段）」，恢复跟进时读回这个阶段（读不到就回到已回复），和结案的做法一样。待你决定里有她的事项时，顶部一条「有 1 件待你决定 [去看]」。
5. **来往记录**：对话气泡（她在左、我们在右，系统事件居中灰字，例如「10 月 27 日 阶段从已回复改成约好发布」）。默认最近 20 条，「看全部」。

**右栏**

1. **码**：体验码（已用/上限进度条、到期日、用量同步时间、停用标记）；活动码（专属连结可复制、账本连结、付款订单、访客）。
2. **资料**：主页、内容类型、市场、语言、邀约批次、联系渠道、级别；每项可点「改」（就地编辑）。
3. **邮箱**：每个邮箱一行，标「默认」「永不联系」「退过信」；「加邮箱」打开 F-04。
4. **发布**：帖子列表（标题、平台、日期、第 1/3/7/30 天播放）；「记下一条发布」打开 F-08。

### 4.4 U-4 执行记录

- **顶部两块**：「正在执行」（每件一行，带开始时间和进度）、「没做成和结果不明」（每件一行，点击跳到 U-1 对应卡片）。
- **运行列表**：时间、做了什么（运行名＋一句摘要）、谁在哪台电脑、结果徽章（完成 / 部分完成 / 失败）。点开一行展开这次运行的操作明细（发了哪些信、谁被结案、哪些没发及原因）。
- **筛选**：只看没做成的、只看发信、只看今天。
- 最上面一行灰字：「最近 3 天系统做过的事，最新的在最上面」。

### 4.5 U-5 设置

设置页现在直接读写项目的「设置」「发信邮箱」「模板」表（飞书或 Postgres 都一样），存了以后下一批执行就用；切换到新数据库时改读写 project_settings、channels、templates / template_versions（design.md 第十二节）。

**布局**：左侧二级导航（发信规则、发信邮箱、模板、选项、接入和执行电脑），右侧当前一节的内容。每节底部固定「保存」「放弃修改」，有未保存修改时页签旁显示圆点，离开时提醒。保存后提示条「已保存，下一批执行就按新规则」，修改记进操作日志（谁、何时、从什么改成什么），每节右上角「修改记录」可看最近 20 条。

**发信规则**（project_settings）

| 分组 | 字段和控件 | 校验和说明 |
| --- | --- | --- |
| 发信 | 每天最多联系几位（数字）、每分钟最多发几封（数字）、退信率暂停线（百分数，带说明「最近 14 天至少发过 20 封才算」） | 大于 0；暂停线 0–100，0 表示不检查 |
| 催信和结案 | 第一次催信天数、第二次催信天数、结案天数（数字）；自动催信起始日（日期，空表示不自动催） | 不能为负；下面一行用这些数字拼出一句话预览：「邀约 5 天没回催第一次，再过 7 天催第二次，再过 7 天还没回就结案」 |
| 不催的人 | 级别多选（S/A/B/C）、对方要求多选；不催的邮箱在「发信邮箱」里设 | |
| 跨项目冷却 | 天数（0 表示不查） | 说明「只在发邀约时检查」 |
| 体验码和活动码 | 体验码默认次数（1–10）、默认天数（1–60）；活动码默认折扣（10–20%）；资料市场到销售市场的对应表（每行一个下拉） | 超出范围当场标红 |
| 体验提醒 | 未用、停滞、快到期各隔几天 | |
| 发布 | 发布识别词（标签输入）、找帖子回看天数 | |
| 找人 | 国家、语言 | |
| 其他 | 时区（只读，显示当前时区；要改请联系开发，因为当天额度、提醒日期、业务日都会跟着变）、说明 | |

**发信邮箱**（channels）

- 列表：邮箱、渠道名、状态（启用 / 停用 / 预热中「今天上限 40」）、每天上限、退信率（近 14 天，带封数）、不自动催的标记。
- 「加邮箱」打开侧滑：邮箱地址、渠道名、每天上限、预热（开关；开时出启用日期、起步上限、每天增加，并画一条两周的额度预览）、退信率暂停线（空=跟项目一样）、不自动催。保存前「检查连接」，通过才能启用。
- 已有往来的邮箱不能改地址，只能停用后新建，表单上写明原因。
- **停用前先列出挂着的事**：有已同意、还没发的信要从这个邮箱发时，停用按钮先展开一张清单（谁、哪封），每件选「改从别的邮箱发」或「撤掉」，处理完才能停用；否则这些信会一直挂着，那几位 KOL 也不会再被催或结案。只改每天上限不用处理，超出的会顺延。

**模板**（templates / template_versions）

- 列表：名称、用途、语言、方向、状态（在用 / 草稿待审 / 停用）、最近修改。
- 编辑页：左边主旨和正文编辑（占位符可从列表点选插入，系统不认识的占位符标红，有就不能提交）；右边预览，可选一位 KOL 填进去看效果，并可和在用版本比较；底部「放弃草稿」「存草稿」「提交审核」，草稿自动保存。Q-11 未确认时的现行做法：模板一有草稿，到新版本批准前都不用于新的信（旧版本也暂停），页面顶部写明会停的事：邀约模板停了就发不了用它的邀约批次；催信 1、2 停了，对应的催信不发（结案照常）；体验到期、未用、跟进模板停了，对应的体验提醒不提。放弃草稿就恢复用旧版本。
- 审核在 U-1 的模板卡（C-09）里做，设置页不能直接批准。

**选项**

- 入库批次、邀约批次：列表＋新增；批次名唯一。
- 标签：列出全项目已用的标签和次数；可改名（全部替换）和合并。

**接入和执行电脑**（只读为主）

- 执行电脑：显示是哪台、这台是不是；换执行电脑写明「在那台电脑上运行 kol executor claim」。
- 业务数据接口地址（可改）、接口密钥（只显示「这台电脑已保存」，改用命令）、飞书群机器人（只显示是否已配置）。
- 数据库：只显示连接到哪里，不显示连接串。

## 6. 现在的页面和这份说明的差距

2026-10-27 按这份说明和设计稿把决策台做完了，包括设置页 U-5（直接读写现在的「设置」「发信邮箱」「模板」表，切换到新数据库时换成新表），每块都在 tafu-test 上点过。和说明不同、或还没做到的只剩这些：

| 地方 | 现在 | 说明 |
| --- | --- | --- |
| 模板自动保存 | 只对已经是草稿的模板自动保存 | 在用的模板一存草稿就暂停使用，所以要点「存草稿」并确认才会变成草稿，打字不会自动停掉它 |
| 放弃草稿 | 编辑在用模板时，把旧文字存在模板的「备注」里，放弃时恢复 | 新数据库用 template_versions 分版本，切换时不再需要 |
