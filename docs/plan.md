# KOL 邮箱批量查找：技术方案设计

Oct 20, 2026 · @Emma

## 整体方案复查（10 月 20 日更新）

讨论到现在，方案已经从“一个找邮箱的脚本”扩成了一个独立的 KOL 平台：找人、查邮箱、存库、运营审核、agent 发信和跟进。下面先列定下来的架构，再列复查时发现的薄弱点和对应的改法。

### 定下来的架构

| 部分 | 选择 | 依据 |
| --- | --- | --- |
| 部署 | 全部放在 Zeabur，一个独立项目，不跟 TAFU 后台混在一起 | 你的项目大多在 Zeabur；找 KOL 的需求不止 TAFU 一个项目 |
| 数据库 | Zeabur 上的 PostgreSQL，作为唯一的总库 | 一次几百到几千人，飞书表很快会到行数上限；agent 做复杂筛选需要真正的数据库 |
| 数据结构 | 两层：所有项目共用的 KOL 总库 + 各项目自己的状态、发信邮箱、模板和沟通记录 | 同一个 KOL 只抓一次；不同项目各自跟进，互相能看到最近谁联系过 |
| 找人和查邮箱 | 后台服务里跑流程，调用 Apify 商店里现成的 actor | 已用 150 人名单实测，见下一节 |
| 运营工作台 | 自建后台网页：名单审核、邮件审核、对话记录、进度看板 | 运营需要审核和把控；直接读写数据库，不用做和飞书的双向同步 |
| agent | 后台每个操作都提供接口，包装成 agent 能调用的工具 | agent 和运营做同样的操作、看同一份数据 |
| 发信 | 独立的外联域名，经过预热，通过外联发信平台的接口发送和收回复 | 不连累公司主域名；平台负责控制发送量和收回复 |
| 飞书 | 只用来发通知和每日汇总 | 运营在飞书里收到需要处理的事，点链接进后台处理 |

### 复查发现的薄弱点

1. **依赖个人开发者的 actor。** 找人和查邮箱的关键环节，用的都是个人开发者发布的 actor（旧的 IG 邮箱 actor、相似账号 actor、YouTube 隐藏邮箱 actor）。它们随时可能改价、失效或下架。改法：每个数据来源做成可以替换的独立模块，同一环节至少准备一个备选；每周用 5 个已知账号自动试跑一次，结果对不上就在飞书里报警。
2. **抓取很慢，不能在网页请求里直接跑。** YouTube 隐藏邮箱 30 个人跑了约 13 分钟，几千人的任务会跑更久。改法：后台要有任务队列和单独的后台进程，网页上只提交任务、看进度，跑完再通知。这在 Zeabur 上多开一个服务就能做到。
3. **Instagram 命中率有天花板。** 以前没找到邮箱的 50 人里，换工具后只多找到 3 个，大多数人本来就没有公开邮箱。改法：在找人阶段就优先挑商业号和简介里有外链的账号，不在查邮箱阶段硬挖。
4. **发信是最大的风险。** 域名信誉一旦坏掉很难恢复，会直接影响后面所有项目。改法：发信前必须先验证邮箱（工具还没选）；新域名先预热几周；每天的发送量设上限；每封邮件都带退订方式，退订的人自动进黑名单。另外，向台湾的 KOL 发商业邮件涉及個資法和反垃圾邮件的要求，具体合规边界我没有核实，正式群发前建议找熟悉台湾法规的人确认。
5. **agent 自动发信可能出错。** 改法：一开始每封邮件都由运营审核后才发；只有在一段时间内没出问题后，才放开跟进邮件自动发。谈价格和签合作始终由人接手。
6. **现有的飞书 KOL 总表要迁移。** 表里已经有的人和联系记录，需要导入数据库，避免重复联系。我还没看到这张表的字段，需要你发一张截图。
7. **小红书和 TikTok 找人还没有可用的方案。** TikTok 按关键词找人实测效果很差，目前只适合查已知账号；小红书的数据来源还没验证。这两块放到后面单独做。

### 建议的开发顺序

先做能马上产生价值的部分，发信放在最后。发信需要的域名预热可以从现在开始，跟前面的开发同时进行。

1. **第一阶段（库和找人）**：搭好数据库和后台框架，导入现有的飞书总表；把已经写好的找人和查邮箱流程接进来，做成后台任务；做名单审核页面和飞书通知。
2. **第二阶段（agent 接入）**：提供 agent 工具，让 agent 能按条件找人、查库、提交任务。
3. **第三阶段（发信和跟进）**：接入邮箱验证和外联发信平台，做邮件审核和对话记录页面，以及 agent 写信、跟进和回复分类。

### 还需要你提供或决定的事

- 现有飞书 KOL 总表的截图（字段名和几行示例）。
- 外联用的新域名：要不要现在注册并开始预热。
- 邮箱验证服务和外联发信平台的选择，我会在第三阶段之前列出几家的对比给你挑。

### 技术选型（定稿）

非核心部分一律用最简单的做法，精力放在找人、查邮箱和发信上。价格为 2026 年 10 月官网所示，按月付费。

| 环节 | 选择 | 理由和备注 |
| --- | --- | --- |
| 语言 | TypeScript（前后端一套），待你确认 | 跟你现有项目一致；现在的 Python 找邮箱流程改写过去，代码量不大 |
| 部署 | Zeabur，一个项目里三个服务：网页和接口、后台任务进程、PostgreSQL | 从 GitHub 自动部署 |
| 任务队列 | 直接用 PostgreSQL 做队列 | 不用另外搭 Redis，少一个服务 |
| 备份 | Zeabur 自带的每日自动备份（Dev 套餐及以上，保留 7 天）+ 每周一次导出到自己的对象存储 | Zeabur 不支持按时间点恢复，也不支持备份到自己的存储，所以自己再存一份保留更久的 |
| 登录 | 一个固定账号密码，放在环境变量里；审核和发信时选操作人名字 | 你定的：非核心流程从简 |
| agent 接入 | 后台自带一个 MCP 服务，用一个密钥鉴权 | Claude 等 agent 通用的接入方式，和网页调用同一套操作 |
| 通知 | 飞书群机器人（Webhook） | 只发消息，不用建飞书应用 |
| 找人和查邮箱 | Apify 商店 actor：IG 相似账号和关键词搜索 + 旧 IG 邮箱 actor；YouTube 频道搜索 + 隐藏邮箱；TikTok 查已知账号；外链页面爬取 | 已实测，见「实测后的定稿」；每个来源做成可替换模块，每周自动试跑 |
| 小红书 | 先用 sian.agency/xiaohongshu-rednote-scraper（支持按关键词搜博主，约 0.3–0.9 美分/人），备选 TikHub 接口 | 还没实测。小红书博主很少公开邮箱，联系方式主要是简介里的邮箱或微信号、所属 MCN、蒲公英，所以这块的沟通方式跟其他平台不同，放在最后做 |
| 发信平台 | 不用第三方发信平台：平台通过 IMAP/SMTP 直接用飞书企业邮箱收发信，自己控制每个邮箱每天的发送量、跟进、退信和退订 | 每月几百到一两千封的量，自己发更简单：省掉平台费，数据都在自己库里，agent 写的信原样发出。少了自动预热，改成手动慢慢加量。飞书的每日发送上限没有公开，待确认。协议通用，以后换 Google Workspace 只改配置。每天要发几百封以上时再考虑 Smartlead 等平台 |
| 邮箱验证 | 先用免费做法：平台自己检查邮箱格式和对方域名能否收信，退信地址自动标为无效；退信比例偏高时再加 MillionVerifier（约 $37/万个） | 各家的准确率都只有厂商自己的说法，开始前用一批已知邮箱自己测一下 |
| 发信邮箱 | 在飞书企业邮箱里绑一个独立的外联域名，开 3–5 个邮箱（能不能加域名待你确认；不行就用 Google Workspace）。新邮箱第一周每天 10–20 封，逐步加到每天几十封 | 不影响公司主域名；即使被飞书判定为批量发信而限制，也只影响外联邮箱 |

收发信不花钱（你定的）：飞书邮箱和 Zeabur 都用现有套餐。另外只有外联域名每年约 $10，以及按量付费的 Apify 抓取费。

### 通用性设计：给多个项目用

原则：**项目之间的不同全部做成配置，不写死在代码里。** 新项目接入时，在后台建一个项目、填好配置就能用，不用改代码。

| 层面 | 怎么做通用 | 例子 |
| --- | --- | --- |
| 项目配置 | 每个项目有自己的：目标地区和语言、找人条件（关键词、种子账号、粉丝范围）、品牌介绍和写信要求、发信邮箱、审核人、飞书通知群 | TAFU 找台湾、繁体中文、生活类博主；另一个项目可以找马来西亚、英文、美妆博主 |
| KOL 总库 | 所有项目共用一份，项目只记录自己的状态和沟通；同一个 KOL 最近被别的项目联系过会提醒，可设冷却期 | 一个人不会在一周内收到两个项目的邮件 |
| 标签和自定义字段 | 内容方向用标签，项目特有的信息放自定义字段，不改数据库结构 | 亲子、婚礼、彩妆；某项目要记“报价”“合作形式” |
| 数据来源 | 每个平台、每个抓取工具都是同一接口的模块（找人、查详情、查邮箱），项目选用哪些来源 | 新增小红书或 CreatorDB，只加一个模块 |
| 发信 | 用通用的 IMAP/SMTP，邮箱挂在项目下 | 飞书邮箱、Gmail 或别的邮箱都能用；不同项目用各自的发信域名 |
| 通知 | 通知地址挂在项目下，先做飞书群机器人 | 各项目的提醒发到各自的群 |
| agent 工具 | 每个工具都带项目参数 | agent 说“给 TAFU 找 50 个亲子博主”，自动按 TAFU 的配置跑 |

不过度设计：只把结构留成通用的，具体模块只做当前用得到的（IG、YouTube、TikTok、飞书邮箱、飞书通知），其他的等有项目需要时再加。

## 实测后的定稿

用 150 个历史 KOL 实测后（数据见项目文件 kol-benchmark/results.md），方案定为：找人和找邮箱都用 Apify actor，CreatorDB 只在需要互动率、粉丝画像等筛选数据，或某个品类自己扩不出人时做备选。下文原先的分析保留作参考，与本节不一致处以本节为准。

| 平台 | 找人 | 找邮箱 | 实测结果 |
| --- | --- | --- | --- |
| Instagram | 相似账号扩量（thenetaji/instagram-related-user-scraper）+ 短关键词搜（apify/instagram-search-scraper） | 旧 actor devil\_port369-owner/instagram-email-phone-scraper-pay-per-result（读商业号公开邮箱字段），读不到的再跟外链 | 旧名单 58/60 复现；新扩的人 42% 到 53% 有邮箱，每个邮箱 1.5 到 2 美分 |
| YouTube | 关键词搜频道（待验证） | 先读简介，读不到再用 dataovercoffee 隐藏邮箱（找到一个 12 美分） | 简介 27/30，隐藏邮箱 29/30 |
| TikTok | 关键词搜用户（待验证） | 读简介 | 10/10 |

所有平台最后按粉丝数、账号类型筛一遍（相似账号会混进品牌店和私人朋友），再去重、导出表格。以前没找到邮箱的 50 个 Instagram 账号，换工具也只多找到 3 个，提高命中率靠的是找人阶段挑对人，而不是换找邮箱的工具。

## 结论

推荐自己写一层轻量的编排程序，做成“分层瀑布”：先用最便宜的方式找人、拿主页，再按成本从低到高挨个查邮箱，查到就停，最后统一验证。底层的抓取不自己维护，Apify actor、官方 API、社媒数据 API 哪个在某一步上最便宜、最准就用哪个，可以随时替换。

- **提高命中率的关键不在换哪个爬虫，而在多查几个地方。** 邮箱散在主页简介、平台商务邮箱、外链页面（Linktree、个人网站）、其他平台的主页，以及 YouTube 需要登录才能看到的商务邮箱里。单个爬虫通常只查其中一两处。
- **最大的一个增量是 YouTube 隐藏商务邮箱。** 一个 Apify actor 的作者自己抽样 8 个 YouTube 频道，其中 6 个设了这个隐藏邮箱，而普通爬虫读不到。已经有 actor 专门做这件事，0.12 美元一个，找不到不收费。
- **找人可以不依赖 CreatorDB。** YouTube 用官方免费 API 按关键词搜，TikTok 和 Instagram 用 Apify 的搜索和“相似账号”actor 往外扩。
- **按 Apify 免费档价格粗算，查 1000 个 KOL 的基础成本在 10 到 20 美元左右**，YouTube 隐藏邮箱按找到的数量另算。具体数字要等用你的历史名单实测。

下面的价格和 actor 信息，除非特别标注，都是我 2026-10-20 直接调 Apify 公开接口查到的，命中率数据都还是作者自己的说法，要实测才算数。

## 问题拆解

整个任务分两段：先“找人”，再“找邮箱”。你现在的两个痛点正好各对应一段：CreatorDB 筛出来人少是找人的问题，命中率低是找邮箱的问题。

命中率有一个天花板：只能拿到 KOL 自己公开过的邮箱。所以提高命中率只有两个办法：把公开过的地方都查一遍，以及优先找那些更可能公开邮箱的人（比如 Instagram 商业号、简介里有外链的人）。

| 邮箱可能在的地方 | Instagram | YouTube | TikTok | 怎么拿 |
| --- | --- | --- | --- | --- |
| 主页简介文字 | 有 | 有（频道简介、视频描述） | 有 | 抓主页时顺便用正则提取，不额外花钱 |
| 平台自带的商务邮箱 | 商业号的“邮件”按钮 | 频道的“查看电子邮件地址”按钮，要登录和过验证码 | 少量商业号有 | Instagram 用能返回公开邮箱的 profile actor；YouTube 用专门的 actor |
| 简介里的外链 | Linktree、Beacons、个人网站 | 同左 | 同左 | 把链接交给网页联系方式爬虫 |
| 同一个人在其他平台的主页 | 互相引用 | 互相引用 | 互相引用 | 从外链和简介里识别出其他平台账号，再查一遍 |

## 可选技术路线对比

没有哪一条路线在所有步骤上都最好，所以推荐按步骤挑。表里的“适合哪一步”就是它在推荐架构里的位置。

| 路线 | 价格 | 优点 | 缺点 | 适合哪一步 |
| --- | --- | --- | --- | --- |
| 第三方达人数据库（CreatorDB、Modash、Influencers.club） | 每月几十到几百美元起 | 筛选方便 | 你已经排除：贵，或人少 | 不用；CreatorDB 可以保留作为一个种子来源 |
| Apify actor 编排 | 按结果付费，大多数每个 0.1 到 0.3 美分 | 自带代理，不用维护；各平台都有成熟 actor；可以换 | 质量参差不齐，很多小作者的 actor 评分低；单个 actor 只查一两处 | 抓主页、外链找邮箱、YouTube 隐藏邮箱、TikTok/Instagram 找人 |
| 社媒数据 API（ScrapeCreators、EnsembleData 等） | ScrapeCreators 据称 10 美元 5000 次起；EnsembleData 按月订阅，约 100 美元/月起（第三方报价，未核实） | 接口稳定、速度快，写代码比 actor 简单 | 只给原始主页数据，邮箱还得自己提取；跟 Apify 价格差不多 | Apify 某个 actor 不稳定时的备选 |
| 官方 API | YouTube Data API 每天 1 万额度免费 | 免费、合规、稳定 | 只有 YouTube 好用；Instagram 的 business\_discovery 不返回邮箱；TikTok Research API 只给学术机构 | YouTube 找人和拿频道简介 |
| 搜索引擎（Serper 等 SERP API） | 约 1 美元 1000 次搜索（第三方报价） | 用 Google 已索引的主页找人，可以按“品类 + 国家 + 邮箱关键词”组合搜，直接找到简介里写了邮箱的人 | 结果重复、有过时的；只是找人的补充 | 找人（偏向“已经公开邮箱”的人） |
| 自建浏览器自动化或 AI 浏览器 agent | 服务器 + 代理 + 账号，每个主页成本和时间都是直接请求的几十倍 | 能做任何人工能做的事 | 慢、贵、平台一改就要修；登录账号会被封 | 不推荐；唯一非它不可的 YouTube 隐藏邮箱已经有 actor 外包 |

“自己开浏览器加大量 IP”这条路，底层就是 Apify 那些 actor 在做的事。自己做只是把代理和维护成本接回来，不会多拿到邮箱，所以不单独推荐。

## 推荐架构

一个小的 Python 编排程序负责串联所有步骤，底层工具都通过 API 调用，每一步的工具都可以替换。

&#91;embedded content: 推荐架构 · 找人、抓主页、五层邮箱瀑布、验证\]

每个 KOL 从第 1 层往下查，哪一层找到邮箱就停，越往下越贵，所以贵的工具只用在前面都没找到的人身上。

- **统一 KOL 表**是核心：记录每个人在每一层查过什么、花了多少、邮箱从哪里来。下次再遇到同一个人直接用缓存，也能看出哪一层最值钱。
- **第 1、2 层不额外花钱**，抓主页时已经拿到了简介和公开商务邮箱字段。
- **第 5 层只对 YouTube**，其他平台到第 4 层为止。
- **第一版形态**：命令行工具，输入名单或关键词，输出 CSV。跑顺了再加网页界面。

| 抓 Instagram 主页 | [apify/instagram-profile-scraper](https://apify.com/apify/instagram-profile-scraper) | 0.26 / 0.16 美分每个 | 2.6 美元 |
| 抓 TikTok 主页 | [clockworks/tiktok-profile-scraper](https://apify.com/clockworks/tiktok-profile-scraper) | 0.3 / 0.1 美分每个 | 3 美元 |
| 抓 YouTube 频道 | 官方 YouTube Data API，或 [streamers/youtube-channel-scraper](https://apify.com/streamers/youtube-channel-scraper) | 免费，或 0.13 / 0.05 美分每个 | 0 到 1.3 美元 |
| 外链找邮箱 | [vdrmota/contact-info-scraper](https://apify.com/vdrmota/contact-info-scraper) | 每页 0.2 / 0.1 美分；另按找到的联系人收费，免费档 10 美分、付费档 0.4 到 0.5 美分 | 付费档约 3 美元；免费档可能到 30 美元 |
| 邮箱验证 | MillionVerifier，或自建 Reacher | 约 37 美元 1 万个（第三方报价） | 不到 4 美元 |
| YouTube 隐藏商务邮箱 | [dataovercoffee/Youtube-Channel-Business-Email-Scraper](https://apify.com/dataovercoffee/Youtube-Channel-Business-Email-Scraper) | 找到一个 12 美分，找不到不收费 | 按找到的数量算，例如找到 300 个就是 36 美元 |

两点要注意。一是 Contact Details Scraper 在免费档上“按联系人收费”是付费档的 20 倍，批量跑的话 Apify 订阅付费档更划算。二是 YouTube 隐藏邮箱虽然单价高，但只对前面几步都没找到邮箱的频道调用，按找到付费，每一分钱都换来一个邮箱。

作为对照，一站式的 [flash\_scraper/creator-leads-scraper](https://apify.com/flash_scraper/creator-leads-scraper) 每个 KOL 0.2 美分，会查简介和个人网站，但不读 YouTube 隐藏邮箱。它的作者抽样 10 个找到 4 个邮箱。它会作为实测里的一个对照组。

## 小红书

小红书可以接进同一套架构，但“找邮箱”那一段要单独设计。找人和抓主页已经有可用的 actor，比如 [socialdatax/socialdatax-xhs-data-api](https://apify.com/socialdatax/socialdatax-xhs-data-api)，过去 30 天有 1882 个用户在用。但小红书博主很少公开邮箱，商单大多走蒲公英平台，或者简介里的微信和邮箱。建议等三个海外平台跑顺了再做，到时候先抽样看看公开联系方式的比例。

## 验证计划

用你的历史名单做一次对照实测，用数据决定每一步用哪个工具，再搭完整流水线。

1. 从名单里取 100 到 200 个，三个平台尽量均衡，最好同时包含以前找到和没找到邮箱的人。
2. 同一批人分别跑三组：你们之前用的 actor（如果知道是哪个）、一站式的 creator-leads-scraper、上面的分层瀑布。
3. 每组记下：找到邮箱的比例、验证通过的比例、每个有效邮箱的成本、耗时；瀑布里再记下每一层各贡献了多少邮箱。
4. 如果名单里有已知邮箱，就拿来算准确率，看找到的是不是同一个。

需要你提供：

- [ ] Apify API token（Apify 后台 Settings → API & Integrations），以及账号是免费档还是付费档
- [ ] 100 到 200 个历史 KOL 名单（平台 + 账号链接即可，有已知邮箱更好）
- [ ] 你们之前用的 actor 名字（Apify 后台 Runs 页面能看到），可选

实测的花费预计在 10 美元以内，其中大头可能是 YouTube 隐藏邮箱。

## 风险与合规

- 批量抓取违反三个平台的服务条款。用 Apify 就是把封 IP 的风险交给 actor 作者，但某个 actor 失效时需要换一个，所以架构里每一步都要能换工具。
- YouTube 隐藏邮箱 actor 是用登录账号加验证码破解实现的，风险在它的作者那边，但也意味着它可能哪天就停。
- 给欧美 KOL 群发邮件要注意 GDPR 和 CAN-SPAM：写清发件人、提供退订、不购买他人整理的邮箱列表。
