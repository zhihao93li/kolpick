# 数据从飞书表搬到 Postgres

2026-10-26 定。用方案 A：先把飞书表的结构原样搬进 Postgres，业务代码不改；分析靠视图。决策台和执行器先留在本机，第二步再搬上服务器。

## 为什么搬

日常数据只在决策台里改以后，飞书表格剩下的好处（不用部署、谁都能打开看、Claude 在哪都能读写、设置有现成界面），Postgres 加上视图也能做到。它的代价却一直在：决策台启动要读一两分钟，为了防人在飞书里手改加了一层层规则，加字段要跑 setup-base，也没法用 SQL 做分析。

## 放在哪

Zeabur 上单独开一个 Postgres 服务，只给 kolpick 用，不放进 TAFU 正式业务的数据库，避免碰到订单数据。分析要用订单时，从 TAFU 只读地取。一个库可以放多个项目，用「项目」一列区分。

## 库里的结构（方案 A）

都在 `kol` 这个 schema 里：

| 表 | 存什么 |
| --- | --- |
| `kol.tables` | 每个项目有哪些表（表名、原飞书表 ID、顺序） |
| `kol.fields` | 每张表的字段，原样存飞书的字段定义（类型、选项、关联到哪张表、公式） |
| `kol.records` | 每一行：项目、表名、记录 ID（沿用飞书的）、全部字段值（一列 JSON）、创建时间、更新时间 |

飞书原来自己做的事，改由插件的存储层（`src/kolops/store/pg.ts`）做：

- **引用字段**：「KOL 跟进」的公开邮箱、粉丝数、主页链接、联系许可、主要平台，读的时候从档案算出来。
- **双向关联**：写一边，另一边跟着改（档案↔跟进、跟进↔接触记录、跟进↔发布内容、运行记录↔操作日志）。
- **系统字段**：更新时间、录入时间用每一行自己的时间；记录人照搬。
- **写入格式**：日期统一存成飞书返回的样子（`2026-12-05T10:00:00.000+08:00`），单选存成数组；第一次用到的选项自动加进字段。
- **写错字段就报错**：不存在的字段、自动算的字段都不让写，和插件对飞书的要求一样。

插件里所有读写飞书表的命令，都由这一层接住；收发信、通讯录还是走 lark-cli。没登记数据库的项目照旧用飞书表，所以两种项目可以在一台电脑上并存。

## 本机缓存

库在新加坡，整张表传过来要几秒（接触记录 13 MB 要 8 秒左右），所以每台电脑在 `~/.kol-ops/cache/db-<项目>-…/` 留一份副本：第一次读整张表，之后只取 `updated_at` 变过的行。每次写都会更新 `updated_at`，所以别的电脑改的也能看到。每次读都会核对行数和首尾 seq，对不上（删过行、重新导入或恢复过）就整张重读；最多 24 小时也整张重读一次。副本里有 KOL 的名字和邮箱，只有本人能读，不在项目文件夹里。

在 tafu-test 上：`kol today` 从 22 秒降到 5 秒，`kol inbox` 从 51 秒降到 6 秒，决策台第一次出数据约 12 秒。

## 分析用的视图

每张表一个视图，名字是 `kol."<项目>/<表名>"`，每个字段一列，类型是对的（数字、日期、单选是文字、多选和关联是数组）：

```sql
select 阶段, count(*) from kol."tafu/KOL 跟进" group by 1;
```

引用字段不进视图，要用就 join 档案的视图。加了字段后运行 `kol db views` 重建。

## 命令

| 命令 | 做什么 |
| --- | --- |
| `kol db import --url <连接串>` | 把飞书表整个复制进库，建视图；不切换。库里已有这个项目时要加 `--replace` |
| `kol db use --url <连接串>` | 这个项目以后的读写都走数据库；连接串只存在本机 `~/.kol-ops/projects.json` |
| `kol db use --feishu` | 切回飞书表（库里的数据不删，但之后不会同步回飞书） |
| `kol db status` | 用的是哪边，库里每张表多少行 |
| `kol db backup` | 导出这个项目的全部数据到 `~/.kol-ops/backups/<项目>/<日期>.json.gz`，留最近 30 份。决策台开着时每天自动做一次 |
| `kol db restore --file <备份> --replace` | 用备份整个换掉库里这个项目的数据；换之前先把现状另存一份 |
| `kol db views` | 重建分析视图 |

## 切换一个项目的步骤

1. 打开「暂停所有发送」，关掉决策台，确认早上的例行任务不在跑。
2. `kol db import --project <项目> --url <连接串>`（之前导过就加 `--replace`），看每张表的行数对不对。
3. `kol db use --project <项目> --url <连接串>`。
4. 打开决策台看一遍，再关掉暂停。
5. 飞书表从这时起不再更新，留着当存档。

先在 tafu-test 上走一遍，正式的 tafu 由你确认后再切。
