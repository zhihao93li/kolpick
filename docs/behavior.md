# kolpick 产品行为规格

这份文档写死系统**怎么做**：有哪些状态、发生什么事会改什么、自动规则什么时候动、几条规则撞在一起时谁说了算、决策台每种卡片给哪些按钮，最后用编号场景把这些规则变成可以逐条测试的例子。

- 为什么这样定、已经定了什么、接下来做什么，看 [design.md](design.md)。
- 数据存在哪张表、哪一列，看 [数据库设计说明书](database-design.md)。
- 和 TAFU 后台的接口，看 [data-api.md](data-api.md)。

规则只写在这里。别的文档要提到某条规则，就引用编号（如 R-04、S-B2），不再抄一遍。

**标记**：带【待改】的规则是 2026-10-27 定下、现行代码还没做到的，列在 design.md 第十二节第 1 步。代码改完就删掉标记。测试按场景编号写，测试名以编号开头（如 `S-B2 已回复的 KOL 退信不结案`）。

## 1. 名词

| 名词 | 意思 |
| --- | --- |
| KOL | 一位博主、团体或品牌，可以有多个平台账号、多个邮箱 |
| 跟进 | 一个项目和一位 KOL 的持续关系，候选（还没邀约）也算 |
| 真人来信 | 能对上发件人的来信，去掉自动回复、退信和系统发件人；以下"来信"都指真人来信 |
| 待认领来信 | 对不上任何 KOL，或者对上了几位 KOL 的真人来信，还没人处理 |
| 待发的信 | 还没终结、会发出邮件的事项：待审、要改、已批准未发出、发失败未处理、结果不明 |
| 例行 | 每天在执行电脑上自动跑的一轮：收信、同步码、催信和结案、体验提醒、找帖子、抓数据 |
| 业务日 | 按项目时区算的一天 |
| 运营 | 在决策台做决定的人；Claude 只做准备，不算运营 |

## 2. 状态

### 2.1 一条跟进的状态

| 维度 | 取值 | 说明 |
| --- | --- | --- |
| 阶段 | 候选、已邀约、已回复、合作中、已约发布、已发布 | 合作走到哪。合作中下面有 TAFU 的细分：体验中、已看报告 |
| 跟进状态 | 进行中、暂缓、结案 | 结案带原因：无回应、对方拒绝、只接固定费、题材不符、退信或邮箱无效、其他 |
| 轮到谁 | KOL、我们、无需动作 | 沟通责任。「等你审核」不存，有待审事项时页面显示【待改：现在 `inbox.ts`、`trialfollow.ts` 会把「等你审核」写进这一列，撤掉没做成的事项后也不还原】 |
| 联系许可 | 允许、永不联系 | 只算当前项目 |

现行代码里「结案」「暂缓」还是阶段的一个取值，体验中、已看报告也和其他阶段平级，结案原因还是旧的 11 个选项（`schema.ts`，切换时按数据库设计说明书 §10.2 映射）；切换到新数据库后按上表拆开（数据库设计说明书 §5.5）。下文的规则按上表写，现行代码按对应的阶段值理解。

### 2.2 不允许出现的组合

| 编号 | 规则 |
| --- | --- |
| T-1 | 结案的跟进，轮到谁必须是「无需动作」，并且有结案原因（历史数据可以缺原因）【待改：现在收到结案 KOL 的来信会写成「我们」而不重开】 |
| T-2 | 体验中、已看报告只能出现在合作中 |
| T-3 | 候选没有首次邀约时间；已邀约及以后必须有（历史数据可以缺） |
| T-4 | 永不联系的跟进不能有待发的信 |

## 3. 不变量

任何时候都必须成立。违反任何一条都是 bug。

| 编号 | 不变量 |
| --- | --- |
| I-1 | 一位 KOL 在一个项目里同时最多一封待发的信。人工审核的信、批量邀约、自动催信三个入口一起算，用同一个「待发的信」判定（含执行中、发失败未处理、结果不明）；只建码不发信的事项不占位置【待改：现在执行中、执行失败的不算占位，`inbox.ts:20-26`】 |
| I-2 | 同一封来信（Message ID）只记一次，重复读到不改任何状态 |
| I-3 | 只有运营在决策台点的「同意」才算批准；Claude 和例行都不能批准【待改：现行代码在「只认决策台的同意」打开时才这样拦，没打开时飞书审核队列里改「发／同意」也算；新数据库没有这个开关】 |
| I-4 | 批准的是卡片上那一份内容：主题、正文、收件人、发信邮箱、附带动作的参数。批准后内容变了，或者对方又来了信，批准作废 |
| I-5 | 结果不明的外部动作不自动重做，等运营确认。超时、断线都算结果不明，不算失败【待改：建码、延期超时现在记成「没做成」，重新审核会再延一次，`trial.ts:91-104`、`send.ts:196`】 |
| I-6 | 已经成功的外部动作不做第二次：码建成了不再建，信发出了不再发，延期做过了不再延 |
| I-7 | 永不联系的 KOL 不会收到任何信；同一邮箱属于永不联系的 KOL 时，用这个邮箱的其他 KOL 在本项目也不发 |
| I-8 | 「暂停所有发送」开着时，不开始任何外发，也不开始建码、延期、开活动码；收信和同步照常 |
| I-9 | 所有碰外部的动作只在执行电脑上、一件一件做 |
| I-10 | 码、用量、订单数以 TAFU 后台为准；同步失败保留上次的值和时间，不当成零 |

## 4. 事件

每个事件写：谁触发、什么时候能做、会改什么。"作废批准"指 I-4 里的作废：已批准但还没开始执行的事项退回待审，没开始的自动任务取消。

### 4.1 找人和邀约

| 编号 | 事件 | 前提 | 结果 |
| --- | --- | --- | --- |
| E-01 | 找到新人入库 | 运营在决策台或 Claude 里发起，花费在预算内 | 新建 KOL、账号、邮箱和跟进（阶段候选）。共用邮箱不合并 KOL |
| E-02 | Claude 补资料 | 无 | 只改称呼、市场、语言、内容类型、合作方向，留修改记录；不能改联系许可、阶段 |
| E-03 | 批准一批邀约 | 运营在决策台批准一条「决定」事项，写明批次、模板和人数 | 批准后给批次里每位符合条件的 KOL 排一封邀约【待改：现在批准只记下同意，要在 Claude 里说「发这批邀约」才发，`state.ts:434`】。条件：阶段候选、有邮箱、本项目没有别的跟进在用这个邮箱、这一批里没有人用同一个邮箱、不在跨项目冷却期内、允许联系 |
| E-04 | 撤回一批邀约【待改：现在没有入口】 | 批准后 5 秒内，或之后任何时候 | 还没开始的邀约全部取消，已经发出的保留 |
| E-05 | 邀约发出成功 | 无 | 阶段改为已邀约，记首次邀约时间，轮到 KOL，下次跟进日期为「第一次催信天数」后 |

### 4.2 来信

| 编号 | 事件 | 前提 | 结果 |
| --- | --- | --- | --- |
| E-10 | 收到真人来信，对上一位 KOL | 发件地址对应的 KOL 里，未结案的只有一位；或者没有未结案的、结案的只有一位【待改：现在对应几位时归给第一位】 | 记最后来信时间，轮到我们，已邀约改为已回复，来信待处理；作废批准（I-4）。跟进是结案的，按 R-05 重开【待改：现在不重开】 |
| E-11 | 收到真人来信，对不上或对上几位 | 无 | 记为待认领来信，进「对不上人」卡片；触发 G-2 |
| E-12 | 认领来信 | 运营在决策台选一位 KOL | 发件地址记进这位 KOL 的邮箱，然后按 E-10 处理，包括重开【待改：现在认领不重开】 |
| E-13 | 标为不相关 | 运营在「对不上人」卡片上点 | 来信不再待认领，不关联任何 KOL |
| E-14 | 收到自动回复 | 无 | 只记录，不改状态，不作废批准 |
| E-15 | 收到退信 | 无 | 按 R-04 |

| E-21 | 运营同意 | 内容完整；允许联系；对方没有在卡片显示的那封之后又来信 | 记批准人、时间、内容指纹；5 秒后才开始执行 |
| E-22 | 5 秒内撤销 | 还没开始执行 | 批准作废，事项回到待审 |
| E-23 | 运营要改 | 无 | 交给 Claude 重写，重写后是新的待审内容，原来的批准作废 |
| E-24 | 运营点「不做了」 | 无 | 事项结束，不发；不会因此禁止联系或结案。「跳过」只是先看下一张卡，不改任何状态 |
| E-24a | 运营点「我发出去了」 | 事项走插件发不了的渠道，运营已经手动发出 | 记一条发出的往来，轮到 KOL，事项结束 |

## 5. 自动规则

### 5.1 例行的顺序

例行按 kol-daily 的顺序跑。前一步没做完，依赖它的步骤当天不做。

1. **收信**（E-10 到 E-15）。任何一个启用的邮箱没收全，第 2 步当天不做。
2. **催信和结案**（R-01 到 R-03）。没有已批准的催信模板时只挡催信，结案照常【待改：现在整个 remind 报错，收信后的结案也停了，`remind.ts:52-55`】。
3. **找帖子**（E-41）。
4. **抓发布数据**（E-42）。
5. **同步码的用量**（E-43）。
6. **体验提醒**（R-06 到 R-09），只起草，不直接发；在第 5 步之后，用的是当天同步到的用量。

### 5.2 闸门

闸门挡的是自动规则。哪道闸门挡哪些规则，见表的最后一列。

| 编号 | 闸门 | 挡哪些 |
| --- | --- | --- |
| G-1 | 「暂停所有发送」开着 | 所有外发和建码类动作；不挡自动结案 |
| G-2 | 项目里有待认领来信【待改】 | 当天的自动催信和自动结案（R-01 到 R-03）；不挡退信结案 |
| G-3 | 有启用的邮箱这一轮没收全【待改：现在超过 400 封只提示，照常催信结案，`sync.ts:57-59`】 | 当天的自动催信和自动结案 |
| G-4 | 这位 KOL 永不联系，或邮箱属于永不联系的 KOL | 一切外发 |
| G-5 | 这位 KOL 已有待发的信（I-1） | 新的邀约、催信、体验提醒；Claude 新起草的回复按 E-20 和旧草稿合成一封 |
| G-6 | 今天已经给这位 KOL 发过信 | 邀约、催信；不挡人工批准的回信 |
| G-7 | 今天已经有自动的信发到同一个邮箱地址【待改】 | 邀约、催信；不挡人工批准的回信 |
| G-8 | 项目每日人数、邮箱每日人数（含预热）已满 | 给今天还没联系过的 KOL 的外发 |
| G-9 | 邮箱最近 14 天退信率达到暂停线（至少发过 20 封才算） | 这个邮箱的外发 |
| G-10 | 不在执行电脑上 | 一切碰外部的动作 |
