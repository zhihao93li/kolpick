# 发出已批准的信

先读 `${CLAUDE_PLUGIN_ROOT}/reference/rules.md`。

1. 试跑：`node "${CLAUDE_PLUGIN_ROOT}/scripts/kol.mjs" send --dry-run`（只发其中几条就加 `--only rec1,rec2`）。
2. 把结果讲给同事：会发给谁（名字、用哪个邮箱、主题），哪些被跳过以及原因（没批准、永不联系、收件人不是这位 KOL、邮箱域名收不了信、今天额度满了、今天已经发过）。邮箱域名收不了信的，请同事去档案里改对邮箱（脚本会提示像不像 gmail.com 之类的拼错）。
3. 同事确认后去掉 `--dry-run` 正式跑。脚本会一封封发，每分钟不超过配置的上限，发完检查投递状态。
   审核记录里填了「体验码动作」的，试跑会显示「发码 xxx，3 次，14 天」「延期 N 天」或「开活动码 xxx，TW，粉丝 85 折」。开活动码成功后，专属连结和账本连结会填进信里，跟进改成「合作中」并记下活动码和两个连结。正式跑时插件先在项目后台建码或延期，成功了才把码和日期填进信里发出，并把跟进改成「体验中」、写上码和到期日；建码或延期失败，这封信就不发，原因写进审核队列的「执行结果」（常见：码名被占用，换个名字重新批；24 小时内已建满 30 个）。
   审核记录填了「发后动作」的（批量处理来信里的拒绝），信发出后就结案或标永不联系；发送渠道是「不发邮件」的直接执行，结果里的 `closed` 是这些人。
   审核选了「不发」的会被撤回（`withdrawn`），对应 KOL 不再停在「等你审核」。
4. 汇报：发出几封、失败几封、结案几位、撤回几条、投递状态。退信或「结果不明」的逐个点名，告诉同事下一步（退信的检查邮箱；结果不明的去飞书邮箱「已发送」里看）。

在决策台里点「同意」的事会马上排队发出，不用再跑这个命令；它主要用来发在飞书里批准的、或者之前因为暂停、额度没发出去的。

审核记录还没批准时，请同事在决策台里点「同意」。「设置」没勾「只认决策台的同意」时，也可以在飞书审核队列把「处理」选「发／同意」。勾了以后，飞书里的批准不算数，`skipped` 会说明；不要替同事在飞书里标批准。
跳过原因是「同意之后内容被改过」的，这一条已经退回「待你审核」，请同事重新看一遍再同意。
报「不是这个项目的执行电脑」时，这台电脑不能发信，请同事到执行电脑上做。
