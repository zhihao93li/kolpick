# 发出已批准的信

先读 `${CLAUDE_PLUGIN_ROOT}/reference/rules.md`。

1. 试跑：`node "${CLAUDE_PLUGIN_ROOT}/scripts/kol.mjs" send --dry-run`（只发其中几条就加 `--only rec1,rec2`）。
2. 把结果讲给同事：会发给谁（名字、用哪个邮箱、主题），哪些被跳过以及原因（没批准、永不联系、收件人不是这位 KOL、今天额度满了、今天已经发过）。
3. 同事确认后去掉 `--dry-run` 正式跑。脚本会一封封发，每分钟不超过配置的上限，发完检查投递状态。
   审核记录里填了「体验码动作」的，试跑会显示「发码 xxx，3 次，14 天」或「延期 N 天」。正式跑时插件先在项目后台建码或延期，成功了才把码和日期填进信里发出，并把跟进改成「体验中」、写上码和到期日；建码或延期失败，这封信就不发，原因写进审核队列的「执行结果」（常见：码名被占用，换个名字重新批；24 小时内已建满 30 个）。
4. 汇报：发出几封、失败几封、投递状态。退信或「结果不明」的逐个点名，告诉同事下一步（退信的检查邮箱；结果不明的去飞书邮箱「已发送」里看）。

审核记录还没批准时，提醒同事去飞书审核队列把「处理」选「发／同意」并勾「确认发出」。同事在对话里明确说「第几条可以发」时，可以替同事把那几条这样标上，但要先复述是哪几条、发给谁。
