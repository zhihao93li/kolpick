# 今天的事 / 处理来信

先读 `${CLAUDE_PLUGIN_ROOT}/reference/rules.md`。

1. 同步来信：`node "${CLAUDE_PLUGIN_ROOT}/scripts/kol.mjs" sync`。这一步只记录来信、把对方改成「轮到我们」，不发信，可以直接跑。
   - 它从上次同步的时间点开始收信，结果里的 `since` 就是从哪天开始的；`warnings` 有内容（某个邮箱信太多没收全）要先讲。
   - `unknownSenders` 是档案里没登记的发件人，可能是经纪人、MCN，或者 KOL 换了邮箱回信。逐个念给同事听，问是不是哪位 KOL；是的话，把这个邮箱加进那位 KOL 档案的「其他邮箱」，下次同步就会自动记上。
   - `autoReplies` 是休假、已收到之类的自动回复，已经记进接触记录，但不算回信，催信照常。
2. 拿清单：`node "${CLAUDE_PLUGIN_ROOT}/scripts/kol.mjs" today`，按这个顺序讲给同事：待处理来信、等你审核、轮到我们、体验码三天内到期、七天内约定发布、今天该催的邀约有几位，最后是「其他渠道要手动处理」。
   - 「等你审核」里 `插件能发` 是 false 的（比如走 Gmail），批了也要同事自己去那个邮箱发，发完把审核记录标成已执行。
   - 「其他渠道要手动处理」是走 Gmail、IG 私信等插件收发不了的对话，插件不会替它们收信、催信。人多时按渠道分组、先讲轮到我们的。
3. 处理来信是**一批一批**做的：先全部分类，再统一起草，最后让同事一次审完。
   - 拿这一批：`node "${CLAUDE_PLUGIN_ROOT}/scripts/kol.mjs" inbox`（默认最早的 30 封，`--limit` 改数量）。每封有对方原话（已去掉引用的旧信）、跟进阶段、现有体验码、`之后回过信`，没体验码的还有 `建议码名` 和 `码名可用`。
   - `之后回过信` 有日期的，多半已经手动回过、只是没取消待处理，一般归「不用回」；拿不准再用 `lark-cli mail +messages --mailbox <渠道邮箱> --message-ids <Message ID> --format json --as user` 看原文。
   - `插件能回` 是 false 的（Gmail、IG 私信）插件回不了，归「不用回」，在总结里列给同事手动处理。
   - 逐封分成四类：
     - **想体验**：回信并发码。草稿照已批准的「发体验码」模板写，码、次数、到期日写成 `{體驗碼}`、`{次數}`、`{到期日}`，不要自己编。`trial: {"action": "发码"}`，码名默认用 `建议码名`；`码名可用` 是 false 就换一个（加后缀，如 `deer_jay2`），先用 `trial-check --code` 查过再写进 `trial.code`。次数、天数不写就用「设置」的默认（现在 3 次、14 天），同事要别的数再写 `uses`、`days`。
     - **要回复**：问问题、谈条件、要延期、答应合作等。对方答应分享、要专属连结时加 `trial: {"action": "开活动码"}`：草稿照已批准的「发活动码」模板写，必须有 `{專屬連結}`，可以用 `{粉絲折扣}`、`{帳本連結}`、`{活動碼}`。码名默认用账号名（`code` 可改，对方指定了尾码就用对方的）；粉丝折扣默认 85 折，要改写 `percentOff`（TAFU 允许 10–20）；市场按档案自动对应，要改写 `market`；对方说了合作页名称就写 `pageName`。已经有活动码的 KOL 不能再开。要延期的加 `trial: {"action": "延期", "days": 7}`，草稿里写 `{到期日}`；码不写就用跟进里的。任何体验码都能延，最长到 60 天后。
     - **拒绝**：对方说不要、没兴趣、不再联系。`after` 选「结案」或「永不联系」（对方明确要求别再联系才选永不联系），`reason` 从结案原因里选（拒绝、题材不符、只接固定费、档期、隐私……）。可以写一封简短道谢的 `draft`，也可以不写；不写就只结案、不发信。
     - **不用回**：自动回复、已经回过、只是道谢、插件回不了的。只取消待处理。
   - 用对方的语言写草稿（台湾 KOL 用繁体、台湾用语），第一行不写主题，回复会接在原邮件串里。每条写一句 `note` 说明为什么这么回，`label` 写一句话摘要（如「发码 deer_jay」「问价格」）。
   - 写成决定文件（一个数组），先试跑再提交：
     ```json
     [{"contact": "rec…", "category": "想体验", "draft": "…{體驗碼}…{到期日}…", "trial": {"action": "发码"}, "note": "对方说想先试", "label": "发码 deer_jay"},
      {"contact": "rec…", "category": "拒绝", "after": "结案", "reason": "只接固定费", "note": "只做付费合作"},
      {"contact": "rec…", "category": "不用回"}]
     ```
     `node "${CLAUDE_PLUGIN_ROOT}/scripts/kol.mjs" inbox --apply 决定.json --dry-run`，没问题再去掉 `--dry-run`。有一条不对就一条都不写，按 `问题` 改好再提交。
   - 提交后：每封要处理的都在审核队列里成了一条「待你审核」，审核项以「[批量] 分类 名字」开头；来信取消了待处理；这些 KOL 的「当前轮到谁」改成「等你审核」。
   - 按分类念给同事听：几位想体验（码名）、几位要回复（各一句）、几位拒绝（结案还是永不联系）、几封不用回、几封要手动去 Gmail / IG 处理。还有没处理完的就再跑一批。
4. 告诉同事草稿已经放进审核队列，去飞书批准后说一声，或者直接用 kol-send 发出。不要自己发。

拒绝和永不联系也走审核：同事批准后，kol-send 发出道谢信（有的话），再结案或标永不联系。
