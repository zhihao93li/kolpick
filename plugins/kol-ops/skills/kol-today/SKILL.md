# 今天的事 / 处理来信

先读 `${CLAUDE_PLUGIN_ROOT}/reference/rules.md`。

1. 同步来信：`node "${CLAUDE_PLUGIN_ROOT}/scripts/kol.mjs" sync`。这一步只记录来信、把对方改成「轮到我们」，不发信，可以直接跑。
   - 它从上次同步的时间点开始收信，结果里的 `since` 就是从哪天开始的；`warnings` 有内容（某个邮箱信太多没收全）要先讲。
   - `unknownSenders` 是档案里没登记的发件人，可能是经纪人、MCN，或者 KOL 换了邮箱回信。逐个念给同事听，问是不是哪位 KOL；是的话，把这个邮箱加进那位 KOL 档案的「其他邮箱」，下次同步就会自动记上。
   - `autoReplies` 是休假、已收到之类的自动回复，已经记进接触记录，但不算回信，催信照常。
2. 拿清单：`node "${CLAUDE_PLUGIN_ROOT}/scripts/kol.mjs" today`，按这个顺序讲给同事：待处理来信、等你审核、轮到我们、体验码三天内到期、七天内约定发布、今天该催的邀约有几位，最后是「其他渠道要手动处理」。
   - 「等你审核」里 `插件能发` 是 false 的（比如走 Gmail），批了也要同事自己去那个邮箱发，发完把审核记录标成已执行。
   - 「其他渠道要手动处理」是走 Gmail、IG 私信等插件收发不了的对话，插件不会替它们收信、催信。人多时按渠道分组、先讲轮到我们的。
3. 同事要处理某封来信时：
   - 用 `lark-cli mail +messages --mailbox <渠道邮箱> --message-ids <Message ID> --format json --as user` 读原文（Message ID 在接触记录里）。
   - 读这位 KOL 的跟进记录和之前的接触记录，弄清楚进展到哪了。
   - 写回复草稿，用对方的语言（台湾 KOL 用繁体、台湾用语）。草稿第一行不用写主题，回复会自动接在原邮件后面。
   - 在「审核队列」建一条：类型「回复邮件」，状态「待你审核」，KOL 关联这条跟进，收件人写对方邮箱，发送渠道写来信的那个邮箱，邮件草稿放正文，我的判断和建议写一两句为什么这么回，审核项写「回复 <名字>：<一句话>」。
   - 把这封来信的接触记录「待处理」取消勾选，跟进的「当前轮到谁」改成「等你审核」。
   - **对方想体验（「想體驗」之类）**：这一条同时就是发码申请，批准一次，插件就建码、填进信里、发出。
     - 码名默认用 KOL 的账号名（去掉 @）。先跑 `node "${CLAUDE_PLUGIN_ROOT}/scripts/kol.mjs" trial-check --code <码名>`，不能用就加个后缀再查，比如 `deer_jay2`。
     - 有已批准的「发体验码」模板就照它写；草稿里码、次数、到期日写成占位符 `{體驗碼}`、`{次數}`、`{到期日}`，不要自己编日期。
     - 审核队列这一条另外填：体验码动作「发码」、体验码 <码名>；体验次数、体验天数空着就用「设置」里的默认（现在 3 次、14 天），同事要别的数再填。
     - 审核项写「发体验码 <码名> 给 <名字>：<次数> 次，<天数> 天」，让同事一眼看出批的是什么。
   - **对方请求延期**：同样一条，体验码动作「延期」，体验码填他的码（不填就用跟进里的），体验天数填要延几天（默认用「设置」的天数），草稿里写 `{到期日}`。任何体验码都能延，包括以前在后台手动建的；最长到 60 天后。
4. 告诉同事草稿已经放进审核队列，去飞书批准后说一声，或者直接用 kol-send 发出。不要自己发。

对方表示拒绝、要求不再联系时，不写回复，按 kol-update 里「永不联系 / 结案」处理，先跟同事确认。
