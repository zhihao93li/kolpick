# 查 KOL、改进度、问数字

先读 `${CLAUDE_PLUGIN_ROOT}/reference/rules.md` 和 `${CLAUDE_PLUGIN_ROOT}/reference/fields.md`。这些都是单条的读写，直接用 lark-cli base。

## 查 KOL
按账号名称或邮箱在「KOL 跟进」和「KOL 档案」里找，再读它关联的接触记录，用几句话讲清楚：阶段、轮到谁、最近一次往来说了什么、下一步。

## 改进度
改之前复述要改哪条、哪些字段改成什么，同事确认再写。常见的：
- 发了体验码：阶段「体验中」，填体验码、体验码上限、体验码到期。
- 约好发布：阶段「已约发布」，填约定发布日期。
- 已发布：阶段「已发布」，并在「发布内容」建一条（KOL 关联、平台、内容链接、发布日期、形式）。
- 改完把「下一步」写成一句人能看懂的话，必要时设「下次跟进日期」。

## 永不联系 / 结案
- 永不联系：在「KOL 档案」把联系许可改成「永不联系」，联系许可原因写上原因；同一个人的其他档案（同邮箱、同账号）也一起改。跟进记录改阶段「结案」、当前轮到谁「无需动作」，选结案原因。
- 结案：阶段「结案」，选结案原因，当前轮到谁「无需动作」。
- 这两种都要先跟同事确认。

## 问数字
读相关的表自己算，回答时说清楚口径（哪个批次、哪段日期、按什么算），例如回复率 = 该批次里阶段不是「已邀约」或最后来信日期不为空的人数 / 该批次邀约人数。分润看「月度结算」。只读，不改表。
