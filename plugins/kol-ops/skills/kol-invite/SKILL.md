# 发起邀约

先读 `${CLAUDE_PLUGIN_ROOT}/reference/rules.md`。发信邮箱用项目「发信邮箱」表里勾了「启用」的。

1. 挑人：从「KOL 档案」里找联系许可「可联系」、还没有跟进记录、有公开邮箱的人，按同事说的方向、粉丝数、批次筛。列出人数和几个例子给同事看。
2. 选模板：在项目飞书表的「模板」里找用途「邀约」、状态「已批准」的，「名称」就是模板名（如「邀约-新版-伴侶」）。按「方向」和 KOL 的合作邀约方向配。只用已批准的模板，不要现写邀约信；要新模板就在「模板」表加一行，状态「待审核」，请同事批。
3. 批次名：请同事在飞书「KOL 跟进」的「邀约批次」里加好新选项（如「第四十批·新版」）。
4. 提交审批：在「审核队列」建一条，类型「决定」，状态「待你审核」，审核项写「邀约 <批次名>：<人数> 人，模板 <模板名>，用 <邮箱>」，要你定什么写清楚名单怎么挑的。等同事在飞书批准。
5. 把选中的档案 record_id 写进一个文件（一行一个），然后试跑：

   ```bash
   node "${CLAUDE_PLUGIN_ROOT}/scripts/kol.mjs" invite --batch <批次名> --template <模板名> \
     --mailbox <发信邮箱> --approval <审核记录 id> --profiles-file <文件> --dry-run
   ```

6. 讲清楚会发多少封、跳过谁（已有跟进、没邮箱、永不联系、额度）。同事说发再去掉 `--dry-run`。当天额度用完时脚本会停，剩下的明天用同样的命令再跑，已发过的不会重发。
7. 汇报发出人数。之后的催信和结案由定时任务（kol-daily）按「设置」里的天数自动做：先催两次，都没回就结案。
